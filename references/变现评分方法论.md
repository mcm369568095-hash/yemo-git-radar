# 变现评分方法论

这份文档解释每个阈值的来由。改分数之前先读一遍，别凭感觉调。

## 一、为什么不是"按星排序"

星数是**存量指标**，衡量的是"过去有多少人觉得不错"。
副业要的是**增量机会**：现在这个东西还有没有人需要、我能不能在别人之前做出来、做出来卖不卖得掉。

一个 5 万星的编辑器，你不可能靠它赚钱——它已经是别人的产品了。
一个 800 星但刚好卡在某个具体需求上的工具，可能是你这周唯一能做完并且卖出去的活。

所以星数在本模型里只出现在两处：
1. 硬门槛（< 50 星剔除，因为需求没被验证）
2. "需求真实"维度里作为 issue/star 比的分母

它**不参与排序**。排序靠六维加权。

## 二、六个维度各自的逻辑

### 可商用 25 分

这是唯一一个"踩了会真出事"的维度，所以给最高权重。

| 许可证 | 分 | 说明 |
|---|---|---|
| MIT / Apache-2.0 / BSD / ISC / 0BSD / Unlicense / CC0 | 25 | 改完直接卖，不用问任何人 |
| MPL-2.0 / LGPL | 15 | 改动的**文件**要开源，可以接受 |
| GPL-2.0 / GPL-3.0 | 5 | 改完的整个作品必须开源，卖闭源产品违法 |
| AGPL-3.0 | 5 | 更狠：部署成网络服务也算分发，必须开源 |
| NOASSERTION / 无 | 8 | 未声明。严格说默认保留所有权利，不能商用 |

**AGPL 的坑**：很多人以为"我没分发源码就不算"。AGPL 明确写了网络服务等于分发。
拿 AGPL 项目做成 SaaS 卖，是这条赛道上最容易踩的雷。

### 上手成本 20 分

按语言给基准分：Python/JS/TS/Go/HTML = 20，Rust/C/C++ = 10-12。

不是语言歧视，是**改得动**的问题。一个不懂 Rust 的人，两天改不动一行；同样两天，Python 项目能改出一个功能。

加分项：README 提到 docker/compose +3，有 homepage +2。

### 中文友好 15 分

- desc 是中文 +8
- README 前 2000 字的汉字占比 > 8% +7
- topics 含 chinese/中文 +3

**注意**：这里必须直接看汉字比例，不能搜"中文"这个词。
早期版本搜关键词，结果全中文的项目被判成"没有中文本地化"，闹了笑话。

中文友好度高的项目，你的"中文化"这条差异化就不成立了，得换打法（比如做场景化）。

### 需求真实 20 分

用 `open_issues / stars` 当"有人在真用"的代理指标：

- ≥ 2%：20 分（很多人用，且真的遇到问题了）
- 0.5% - 2%：16 分
- < 0.5%：10 分（可能只是被收藏，没人真用）

加分：有 Discussions +2（社区活着），近 7 天有 push +2（项目没死）。

**这个指标的局限**：issue 多也可能是维护不勤。所以它只当代理，不当定论。

### 交付轻重 10 分

仓库体积：< 5MB = 10，< 30MB = 7，< 100MB = 4，更大 = 2。

体积大意味着依赖地狱。一个 200MB 的仓库，光 clone 和装环境就能耗掉一晚上，
这种项目"今晚能动手"是假的。

### 时效红利 10 分

- 近 30 天新建：10
- 60 天：7
- 90 天：5
- 半年：3
- 更老：1

越新越少人做，越容易吃到第一波。但新也意味着坑多，这是权衡。

## 三、可接手度（±调整项）

这一项是模型的良心。没有它，报告会变成"技术新闻摘要"——全是 AI 基础设施，普通人一个都接不了。

扣分：
- 要 GPU / CUDA / 集群 / 分布式 / 推理引擎：**−12**
- 是 framework / sdk / infrastructure / runtime / compiler：**−6**
- 大厂 Organization 主导且 > 2 万星：**−8**（路线不由你定，只能做外围）

加分：
- 能对上 13 个具体行业之一（玄学/教育/电商/视频/设计/内容/客服/数据/文档/财税/求职/本地生意/健康）：**+8**

**为什么行业加分这么高**：因为"卖给想做 AI 工具的人"你找不到人，
"卖给做玄学号的号主"你能直接去小红书搜到一千个。买家越具体，成交越可能。

## 四、硬淘汰的四个理由

1. **已归档 / 一年没提交**：代码可能跑不动，你的两小时会全花在修依赖上。
2. **星数 < 50**：需求没被验证。你可能做出了一个只有作者自己需要的东西。
3. **纯 awesome 清单 / 合集**：跑不起来，交不出去。只能当读物，不能当商品。
4. **合规红线**：jailbreak、破甲、绕过审核/付费墙、破解、盗版、外挂。

第 4 条是硬的，不看分数。这些东西技术上能跑，但拿去做商品会让买家（和你）出事。
雷达宁可漏掉机会，也不能把人往坑里带。

## 五、三行落地的生成逻辑

`改哪一处` 从"形态"推，不从"缺口"随便挑：

| 形态 | 默认动作 |
|---|---|
| web 应用 | 界面中文化 / 部署公开 demo / 做行业预设 |
| 引擎库 | 包一层网页界面 / 补中文文档 / 补真实案例 |
| 命令行 | 封装成双击脚本 / 写图文教程 / 输出做成成品 |
| Agent 技能 | 改中文指令版 / 打包成技能 / 做效果对比 |
| 模板主题 | 换本地行业案例 / 写安装说明 / 补配套素材 |
| 模型数据 | 做一键安装包 / 中文说明 / 场景脚本 |

`卖给谁` 先认行业（13 类），认不出再按形态兜底。
**行业优先于形态**，因为具体的人才是能收钱的人。

`怎么交付` 按形态定：web 应用卖部署费、模板卖 zip、技能卖安装包、命令行卖教程。

## 六、调参建议

想更保守（只看稳的）：把 S 阈值从 80 提到 85，`--top` 降到 5。
想更激进（多看机会）：`--min-stars` 降到 100，接受 B 级也看。

**别做的事**：不要为了凑数把 GPL 项目的权重调高。那是在帮人踩坑。
